# 08 — Стратегія тестування

Додано eng review 2026-06-10 (Issue 7): аудіорушій критичний для надійності (засіб до існування
оператора проходить через нього 8 годин на день), тому тестованість закладається зараз —
дороблювати fake-device seam у код NAudio пізніше — болісно.

## 1. Архітектура тестованості: device seams

Аудіоядро ніколи не торкається класів пристроїв NAudio напряму. Два інтерфейси ізолюють усе
обладнання:

```
IAudioCaptureDevice          IAudioRenderDevice
  Start()/Stop()               Start()/Stop()
  event DataAvailable(buf)     int Read(float[] buf)   // pull-based, mirrors WASAPI callback
  Format                       Format
  event StateChanged           event StateChanged
```

- **Виробничі реалізації** обгортають `WasapiCapture` / `WasapiOut` (+ interop відмови від ducking).
- **Тестові реалізації**: `FileCaptureDevice` (подає WAV так, ніби сказано в мікрофон, у
  контрольованому темпі), `MemoryRenderDevice` (збирає відрендерений вихід для перевірок),
  декоратори `FaultyDevice` (кидають / зникають / зависають на команду, щоб ганяти шляхи збоїв).

`DeviceMonitor` так само за `IDeviceMonitor`, тому події видалення пристрою можна викликати
синтетично в тестах.

## 2. Шари тестів

| Шар | Фреймворк | Що покриває |
|---|---|---|
| Unit (аудіоядро) | xUnit | Машина станів, поведінка мікшера, рампи приглушення (ducking), правило одного відтворення, переходи OFF AIR, watchdog, політика дрейфу — усе проти fake-пристроїв |
| Unit (DSP, golden files) | xUnit + еталонні WAV | Trim, узгодження гучності, fade-out: подати відомий вхідний WAV → порівняти вихід зі збереженим еталоном (точно до семпла в межах допуску) |
| Unit (storage) | xUnit | Атомарні записи репозиторію, обробка пошкоджених файлів, orphaning, import merge/replace |
| Unit (services) | xUnit | Реєстрація/показ конфлікту HotkeyService, повнота LocalizationService |
| Integration (ручний + скриптований) | чек-лист | Реальні пристрої, реальний VB-CABLE, реальний дзвінок Zoho — те, що може перевірити лише обладнання |

## 3. Необхідне покриття тестами за компонентами

### AudioEngine / машина станів
- Кожен перехід у діаграмі 06 §2: Stopped→Live, Live→OffAir→Live, Live→Degraded
  (втрата пристрою через `FaultyDevice`), Degraded→Live (перебудова успішна), Degraded→Stopped
  (повтори вичерпано), OffAir→Degraded.
- Watchdog: запит render зависає > 500 ms ⇒ перебудову запущено рівно один раз.
- Відмову від ducking викликано на кожному (пере)старті потоку (перевірити через test double).
- Політика дрейфу: overrun ⇒ найстаріші семпли відкинуто + залоговано; underrun ⇒ тишу вставлено +
  залоговано (сконструювати з невідповідними fake-годинниками).
- Тривога DEGRADED піднята через канал тривоги навіть коли `monitorEnabled=false`.

### Mixer / PhrasePlayer
- Одне відтворення: тригер під час відтворення замінює (за замовчуванням) або ігнорується (перемикач) —
  перевірити вихід на рівні семпла через `MemoryRenderDevice`.
- Стоп застосовує лінійний fade на 10 ms (golden file: немає розриву > порогу).
- Рампа приглушення (duck): гілка мікрофона досягає `micDuckDb` у межах `duckRampMs` ±1 буфер і повертається після.
- Коректність mono→stereo upmix на краю cable.

### Recorder (golden files DSP)
- Trim: провідну/хвостову тишу видалено, 150 ms padding збережено (еталонні WAV).
- Узгодження гучності: вихідний RMS у межах ±0.5 dB від цілі `micReferenceRms`; пік ніколи не перевищує
  −3 dBFS (тест із тихими, гучними і клипованими дублями).
- OFF AIR: відкриття recorder призупиняє гілку cable (перевірити, що жодні семпли не доходять до пристрою cable,
  поки відкрито), стан відновлено при закритті.
- Disk-full: збій writer посеред дубля чисто перериває, тимчасовий файл видалено, бібліотека недоторкана.

### Storage / repository
- Симуляція kill -9: перервати між tmp-write і rename ⇒ оригінал цілий (вже
  критерій виходу Phase 2; автоматизовано, не вручну).
- Пошкоджений `library.json` ⇒ старт входить у шлях відновлення (завантажити найновішу копію, показати повідомлення)
  — ніколи не падати, ніколи тихо не стартувати порожнім.
- Відсутній/пошкоджений WAV ⇒ фразу позначено зламаною; відтворення коректно відмовлено.
- Видалення ⇒ метадані зникли, файл перейменовано `deleted-{id}.wav`, щоденна копія все ще включає його.
- Round-trip export→import: без втрат для активних фраз; orphan виключено з експорту.

### Services
- HotkeyService: збій реєстрації показує типізовану помилку (перевірити з попередньо зареєстрованою
  конфліктною гарячою клавішею); повторна реєстрація після перепризначення.
- Повнота локалізації: тест перелічує кожен ключ ресурсу і перевіряє наявність у
  `uk`, `pl` і `en` — відсутній переклад валить CI, а не оператора.

## 4. Чек-лист ручного тесту дзвінка (тільки обладнання може це перевірити)

Виконати на цільовій машині проти реального дзвінка Zoho Voice (спершу Phase 0; повторюється на
пілоті після Phase 3 і перед v1):

- [ ] Дальній кінець чує фразу чітко; розбірливість не зачеплена Chrome NS/EC/AGC
- [ ] Дальній кінець чує живий голос між фразами; немає стрибка рівня на межах фраз
- [ ] Приглушений (ducked) мікрофон справді звучить приглушеним для дальнього кінця (перевірка після AGC)
- [ ] Гаряча клавіша стопу `Pause` спрацьовує, поки Chrome у фокусі; відтворення зупиняється за мить
- [ ] Затримку (latency) mouth-to-Chrome виміряно і записано (метод loopback-запису)
- [ ] Комунікаційне приглушення (ducking): почати/зупинити дзвінок повторно; рівень потоку cable лишається сталим
- [ ] Репетиція запасного варіанту під час дзвінка: переключити мікрофон Chrome на апаратну гарнітуру; дзвінок триває
- [ ] Висмикування пристрою: від'єднати гарнітуру під час дзвінка ⇒ тривога DEGRADED чутна на системному пристрої за замовчуванням
- [ ] Вбити процес застосунку під час дзвінка ⇒ Windows перезапускає його; з'являється toast відновлення
- [ ] 8-годинний soak: події дрейфу залоговано < кількох на годину; RSS рівний
