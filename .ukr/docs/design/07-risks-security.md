# 07 — Обробка помилок, безпека і приватність, ризики

## 1. Обробка помилок і граничні випадки

| Випадок | Поведінка |
|---|---|
| VB-CABLE не встановлено / видалено | Рушій STOPPED; борд вимкнено з чітким повідомленням; setup wizard знову відкривається |
| Мікрофон від'єднано під час дзвінка | Авто-повтор перебудови з backoff; банер DEGRADED + тон тривоги на **системному пристрої за замовчуванням** (вона повинна знати, що клієнт її не чує) |
| Комунікаційне приглушення (ducking) Windows послаблює потік cable, коли починається дзвінок | Рушій відмовляється від цього на рівні сесії (`SetDuckingPreference`); майстер встановлює Sound → Communications → "Do nothing" як запасний варіант (рішення #12) |
| Сесію AdaVoice заглушено у Volume Mixer | Інакше тихий повний збій — майстер/самотест читає стан mute сесії і позначає це |
| Пристрій виходу за замовчуванням — CABLE Input (поширений стан після встановлення) | Кожен системний звук грав би клієнту — майстер перевіряє пристрої render + communications за замовчуванням і попереджає |
| Спроба запису, коли дзвінок міг би бути активним | Витік неможливий: Recorder відкрито ⇒ OFF AIR (cable призупинено, банер) за дизайном (рішення #11) |
| Перенумерація пристроїв (оновлення Windows, переперелік USB) | Пристрої зберігаються за MMDevice ID із запасним варіантом за дружньою назвою; запит, якщо неоднозначно — ніколи не вгадувати |
| Збій застосунку | `RegisterApplicationRestart` перезапускає; авто-відновлення рушія + toast "engine recovered"; файл heartbeat дозволяє перезапуску виявити нечистий вихід і залогувати його |
| Налаштування приватності мікрофона Windows блокують десктопні застосунки | Попередня перевірка майстра з посиланням на виправлення (Settings → Privacy → Microphone) |
| Файл фрази відсутній / пошкоджений | Кнопка показує зламаний стан; відтворення відмовляє коректно; перевірка бібліотеки під час старту |
| Два екземпляри AdaVoice | Single-instance mutex; другий запуск фокусує перше вікно |
| Диск повний під час запису | Попередня перевірка вільного місця; збій writer перериває дубль із повідомленням; тимчасовий файл прибрано |
| VB-CABLE на 44.1 kHz (його поширене значення за замовчуванням) | Майстер перевіряє формат shared-mode = 48 kHz і пропонує виправити — уникає постійного resampling на гарячому шляху |
| Пристрій із невідповідною частотою дискретизації під час виконання | Рушій робить resample; залоговано |
| Виявлено формат захоплення низької якості (8/16 kHz) | Явне попередження (старий запобіжник; дротову гарнітуру підтверджено, тому малоймовірно) |
| Render callback зависає | Сторожовий таймер (watchdog) примусово перебудовує потік після 500 ms тиші на боці запиту |
| Overrun / underrun дрейфу годинника | Відповідно drop-oldest / insert-silence, обидва залоговані; повторювані події — це виправлення Phase 1, а не прийнятна поведінка (06 §1) |

## 2. Безпека і приватність

- **Повністю локально:** немає мережевих викликів, немає телеметрії, немає акаунтів. Усе аудіо і метадані лишаються
  на машині під `%LOCALAPPDATA%\AdaVoice\` (застосовуються ACL профілю користувача).
- Записи — це **власний голос** оператора — усе одно персональні дані. Резервні копії/експорти — це
  **незашифровані zip** у v1; це задокументовано для користувача. Зашифрований експорт — заплановане
  покращення.
- Видалені фрази лишаються на диску як сирітські файли (orphaned) (рішення #14) — задокументовано для користувача;
  справжнє видалення означає видалення файлу вручну або через майбутній інструмент "purge orphans".
- Застосунок ніколи не захоплює бік клієнта в розмові — лише мікрофон оператора,
  і лише поки вона записує фрази або запускає наскрізну передачу (passthrough) наживо.
- Інсталятор **не підписаний кодом у v1** (рішення #19): SmartScreen покаже попередження
  "unrecognized app" при першому встановленні. Прийнятно для особистого/сімейного використання; посібник користувача
  пояснює попередження. Переглянути (сертифікат EV/OV), якщо застосунок коли-небудь буде розповсюджуватись.

## 3. Юридична / етична / продуктова безпека

- **Прозорість і згода:** AdaVoice відтворює *попередньо записані фрази справжнього оператора, який
  присутній і веде розмову*. Це засіб ефективності — не автоматизація дзвінків,
  не імітація голосу.
- **Без обману за дизайном:** продукт свідомо виключає функції, що симулюють
  присутність — без авто-відповідей, без запланованого відтворення, без роботи без нагляду. Один тригер =
  одне людське рішення.
- **Відповідність робочому місцю/платформі — вирішено (2026-06-13, рішення #20):** не потрібна жодна угода
  з роботодавцем чи щодо умов Zoho (роботодавець лояльний). Більше не є перешкодою. Позиція продукту щодо
  прозорості/згоди вище (справжній оператор присутній, один тригер = одне людське рішення)
  — це те, що тримає його доречним для використання.
- Якщо платформа записує дзвінки, AdaVoice не додає нових даних клієнта — аудіо фрази вже
  є власним голосом оператора.

## 4. Реєстр ризиків

| Ризик | Вплив | Імовірність | Пом'якшення |
|---|---|---|---|
| Застосунок — єдина точка відмови для її живого мікрофона (passthrough вмирає → клієнт чує тишу) | Високий | Середня | Сторожовий таймер (watchdog) + авто-перебудова; `RegisterApplicationRestart`; тривога на системному пристрої за замовчуванням; **запасний варіант відрепетировано у Phase 0** (перемикання мікрофона Chrome під час дзвінка протестовано на живому дзвінку); spike Voicemeeter робить план B відомо-робочим |
| Обробка Chrome/Zoho погіршує аудіо фрази (NS, EC, **AGC**) | Середній | Середня | **Spike Phase 0 на реальному дзвінку Zoho Voice з AGC явно в тестовій матриці** (перешкода go/no-go); записи з узгодженою гучністю; вимкнути перемикачі NS/AGC, якщо доступні |
| AGC протидіє приглушенню (ducking) / переврівнює фрази (сприйняті рівні ≠ налаштовані рівні) | Середній | Середня | Налаштувати значення duck і gain за замовчуванням проти вихідного сигналу після AGC у Phase 0; крок калібрування дає стабільну базову лінію |
| Невідповідність гучності фраз і живого голосу руйнує ілюзію "ніби сказано" | Середній | Висока (з лише піковою нормалізацією) | Узгодження гучності за RMS до каліброваного майстром референсу мікрофона (рішення #13) |
| Наскрізна затримка (latency) перевищує цілі (внутрішній буфер VB-CABLE + буферизація Chrome не в бюджеті застосунку) | Середній | Середня | Phase 0 вимірює **mouth-to-Chrome**; затримку VB-CABLE з панелі керування задокументовано; буфери налаштовано з вимірювання (A11) |
| Тертя при встановленні VB-CABLE (драйвер, адмін, попередження антивірусу, захоплення пристрою за замовчуванням) | Середній | Середня | Майстер зі скриншотами, verify-after-install, перевірки пристрою за замовчуванням + формату + приватності + mixer; адмін-доступ підтверджено наявним |
| Луна/зворотний зв'язок (monitor протікає в мікрофон) | Середній | Низька | Дротову гарнітуру підтверджено; моніторинг іде лише в навушники |
| Повзуча затримка (latency) протягом довгих сесій (дрейф буфера) | Середній | Середня | Обмежений буфер із drop-oldest/insert-silence + логування; 8-годинний soak test у Phase 1 |
| Гаряча клавіша стопу непридатна (відсутня клавіша Pause) або конфліктна | Низький | Низька | Перевірка наявності майстром + живе натискання для тесту; запасний `Ctrl+F12`; виявлення конфлікту при реєстрації |
| Політика роботодавця/платформи забороняє інструмент | Високий | **Вирішено (2026-06-13)** | Не потрібна угода з роботодавцем/Zoho (роботодавець лояльний); ризик закрито (рішення #20) |
| Оператор відхиляє UX (кнопки, робочий процес, фокус) | Середній | Невідомо → вирішено рано | Контрольований пілот на пів дня після Phase 3 (рішення #20), а не перший контакт на Phase 5 |
| Граничні випадки WASAPI (застосунки exclusive-mode крадуть пристрої) | Середній | Низька | Скрізь shared mode; логіка перебудови |
| Особливості NAudio/драйвера, специфічні для її обладнання | Середній | Невідомо | Spike Phase 0 виконується на реальній цільовій машині |

## 5. Збірник запасних дій (для посібника користувача)

1. **Аудіо фрази звучить погано для клієнтів** → перезапустити калібрування; перевірити налаштування NS+AGC
   Zoho/Chrome; якщо стійко, переключитися на відрепетировану конфігурацію Voicemeeter.
2. **Мікрофон мертвий під час дзвінка (тривога DEGRADED)** → у Chrome/Zoho переключити мікрофон назад на
   апаратну гарнітуру (≈ 30–60 с; **цей точний крок відрепетировано у Phase 0 на живому
   дзвінку**), завершити дзвінок, перезапустити AdaVoice (або дати Windows перезапустити його після збою).
3. **Застосунок не запускається / рушій не переходить у LIVE** → запустити самотест setup wizard; перевірити, що
   пристрої CABLE існують у налаштуваннях Windows Sound; перевстановити VB-CABLE, якщо відсутній.
4. **Windows каже "Windows protected your PC" при встановленні** → очікувано (непідписаний інсталятор,
   рішення #19): More info → Run anyway. Задокументовано зі скриншотом у посібнику користувача.
